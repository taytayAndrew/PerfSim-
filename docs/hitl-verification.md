# HITL 端到端验证清单

## 准备工作

### 1. 启动 Server
```
cd D:\perfsim\server
node src/index.js
```
预期输出：
```
PerfSim Server running at http://localhost:3000
Rules loaded: 2
```

### 2. 加载 Extension
- 打开 Chrome → `chrome://extensions/`
- 开启「开发者模式」
- 点「加载已解压的扩展程序」→ 选择 `D:\perfsim\extension\dist`

---

## 验证项

### A. Server 离线提示
1. **不启动** Server，打开 Popup
2. ✅ 应看到黄色警告：「无法连接到 PerfSim Server（localhost:3000），请先启动服务」
3. 「分析页面」按钮应为灰色（disabled）

### B. 规则列表加载
1. 启动 Server，打开 Popup
2. ✅ 应看到规则选择框：「串行请求链并行化」和「关键资源预加载」，均默认勾选
3. ✅ 每条规则右侧有置信度标签（medium/high）
4. ✅ 底部有「更多规则即将推出…」灰色文字

### C. 分析页面
1. 打开任意 HTTP/HTTPS 页面（推荐：https://m.jd.com 或任意有 API 调用的页面）
2. 打开 Popup，确认 URL 显示正确
3. 确保至少勾选一条规则，点「分析页面」
4. ✅ 按钮消失，出现旋转图标 + 「分析页面中…」
5. 等待分析完成（约 30-60s）
6. ✅ 出现 AnalyzeView：
   - 显示 LCP / FCP 基线指标
   - 显示发现的串行链数量
   - 有「开始推演优化」按钮

### D. 串行链列表
1. 分析完成后，如有发现串行链：
2. ✅ 点「查看串行链详情」展开列表
3. ✅ 每条链显示：请求路径（无域名/参数）、深度、总延迟
4. ✅ 点击再次收起

### E. 推演优化
1. 点「开始推演优化」
2. ✅ Popup 出现 4 个步骤指示点：
   - 录制页面网络请求（蓝色脉冲）
   - 分析串行请求链（灰色）
   - 测量优化前基线（约 60s）（灰色）
   - 注入优化脚本并测量（约 60s）（灰色）
3. ✅ 步骤点随进度依次点亮
4. ✅ 当前页面出现黑色半透明遮罩 + 「推演中，请勿操作…」
5. 等待约 3-5 分钟

### F. 推演完成 - Popup
1. 推演完成后 Popup 显示：
2. ✅ SimulateView：before/after LCP/FCP 对比
3. ✅ 节省时间（如「节省 800ms」）
4. ✅ 蓝色提示框：「完整报告已在新标签页打开」
5. ✅ 页面遮罩消失

### G. ReportTab
1. 新 Tab 自动打开报告页
2. ✅ 顶部结论摘要（产品层）：
   - badge（高价值优化 / 中等优化 / 优化有限 / 建议排查后端）
   - 一句话结论文字
3. ✅ 指标对比卡片：LCP before → after，FCP before → after
4. ✅ 技术细节（串行链列表，可折叠）
5. ✅ 「导出 HTML」按钮可点，下载 .html 文件，双击能在浏览器打开
6. ✅ 历史记录区域（如有多条记录，显示历史按钮可切换）

### H. 无优化空间提示
1. 找一个没有 API 串行链的简单页面（如 https://example.com）
2. 分析 + 推演后：
3. ✅ Popup 显示 noOptimization 结果（savedMs: 0）
4. ✅ ReportTab 结论：「未发现可并行化的 API 串行链」

### I. 错误处理
1. 分析过程中关掉 Server（Ctrl+C）
2. ✅ 推演失败后 Popup 显示红色错误框 + 中文错误原因
3. ✅ 显示「重试」按钮，点击触发重置

### J. 自定义规则导入
1. 准备一个合法规则文件（参考 `server/rules/rule-resource-preload.js` 格式）
2. 在 Popup 底部点「导入自定义规则 (.js)」
3. 选择规则文件
4. ✅ 出现「已导入：xxx」绿色提示
5. ✅ 规则列表刷新，新规则出现

### K. 登录页跳转检测
1. 分析一个需要登录的页面（Session 已过期）
2. ✅ 检测到跳转到 login/signin URL 时，错误提示：「Cookie 可能已失效，页面跳转到登录页」

## 已知限制（Out of Scope）
- 部分动态 API（参数每次不同）无法被拦截缓存，报告中会列出并标注
- Web Worker 内的请求暂不拦截
- 推演结果为「优化潜力上限」，非精确预测

---

## 快速冒烟（最小验证）
只需完成 A → B → C → E → F → G 即可覆盖核心路径。
